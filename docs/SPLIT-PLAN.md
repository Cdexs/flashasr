## 0. 结论先说

1. **两个独立应用，用户自己选装哪个**（Gavin 10-29：「这是两个独立的应用，由用户决定选择哪一个进行安装」）：
   - **飞音输入法**（voice-ime）：热键、录音、浮层、上屏、词库、场景感知。**不带任何识别模型**，Windows / macOS 都能单独安装。
   - **flashasr**（本目录）：识别服务，**只做本地实时**（SenseVoice 预览 + Qwen3-ASR 1.7B 精解 + 强制对齐）。不做在线 FunASR 中转（Gavin 10-29：「我们自己后端的 FlashASR 就不保留直连 FunASR 的能力了，不做这个中转了，只做我们本地实时语音识别服务。」）。去掉「本地模型 - 快速」（performance）、「本地模型 - 长音频」（accuracy）、在线 Qwen Audio。
2. **输入法两条识别路径**（Gavin 10-29 最终定：「剥离出的前端输入法要保留直连阿里 FunASR 服务的能力。也就是说，前端输入法既可以直连阿里的 FunASR 服务，也可以连接我们自己部署的 FlashASR 服务。先记下来，后面改前端语音输入法的时候再实施。」）：
   - **连 flashasr**（本机或另一台电脑）：本地实时识别，完整处理环节。
   - **直连阿里 FunASR**：用户自己的阿里 Key，不装 flashasr 也能用（输入法保留今天的直连代码）。
   - 两次改口记录：10-29 先确认保留 → 随后改为不保留 → 最终改回保留（以本条为准）。**P3 改输入法时实施**。
3. **处理环节由前端用接口参数逐次告诉服务端**（Gavin 10-29：「接入的前端应该可以通过接口里面的参数告诉后端的服务是否开启输出优化，还有开启翻译这些，所以接口参数应该有这些参数」）：输出优化、翻译、数字规整、补标点、繁简、去句末标点，都是 `run-task` 的参数。服务端不替终端保存这些开关。
4. **每个终端在服务端有一份「终端档案」**，只存服务端才有的东西：声纹（以后加麦克风近场标定）。今天只有本机主人才有的声纹剔除，变成每个终端都有。一个终端默认就是一个人用（Gavin 10-29）。**词库也是每个前端单独的**（Gavin 10-29「词库也是每个前段单独的」），每次随请求带上，服务端不掺机主词库。
5. **输出优化（大模型）移到服务端**，大模型用服务端**一份统一配置和密钥**，与终端用户无关（Gavin 10-29：「服务端大模型用统一的配置的秘钥，跟前端的用户无关」）。整条文字处理只在服务端一处，DEC-036 的顺序不再跨两边。
6. **首次使用弹连接向导**（Gavin 10-29：「暂时还不存在用户升级的问题。所以第一次使用的时候应该弹出配置连接服务的一个向导」）。
7. **一期识别服务的代码基本都能直接搬**：远程会话、网关、配对、TLS 钉扎、逐字时间、服务端文字处理，10-17~10-19 已在 voice-ime 里做完并测过。这次主要是**搬家 + 换主次**。
8. **macOS**：这次只保证 macOS 输入法能连 Windows 上的 flashasr；flashasr 本身的 macOS 版（本地实时引擎移植）以后单独立项。

## 1. 现状（以代码为准）

| 项 | 现在在哪 | 说明 |
| --- | --- | --- |
| 识别引擎（预览、精解、对齐、VAD、声纹） | voice-ime 主程序进程内 | `src/transcription/`、`src/localrt_session.rs`，约 3.3 万行 |
| 识别服务（对外） | voice-ime 内核 `src/asr_service/` + 独立网关 `feiyin-asr-gateway` | 网关管 TLS / 鉴权 / 协议，经本机 IPC 调内核；**不为远程单独加载模型**，借本机本地实时档那一份 |
| 远程终端（客户端） | voice-ime `src/transcription/feiyin_remote.rs` + `qwen_inference.rs` 的 `transcribe_streaming_feiyin` | 「自家识别服务（另一台电脑）」选项，已能连 |
| 在线 FunASR | voice-ime 直连阿里 `qwen_inference.rs` | 用用户自己的 API Key |
| 文字处理 | 本机：`main.rs` `run_pipeline_core`；远程：`asr_service/text_stage.rs` | 同一批函数，远程只开放 ITN / 补标点 / 翻译三个参数（Gavin 10-17） |
| 设置界面「识别服务」页 | voice-ime `ui/src/pages/AsrServer.tsx` | 启停、终端、连接码、外网地址 |
| 模型 | `models/`（安装包不带，用户另下） | SenseVoice、Qwen3-ASR 1.7B gguf、对齐 0.6B、silero-vad、CT 标点、日韩标点、声纹 campplus、opus-mt / nllb 翻译 |

一期留下的三个缺口，拆分时必须一并补上：

- **服务端文字处理没跟上 DEC-112**。本机最终文本是「剥光标点 → 标点模型整段重打」，远程会话的 `text_stage::apply_final` 只在「文字无有效标点」时才补标点。同一段话走本机和走服务，标点会不一样。
- **服务端会话读的是服务端机主的词库**（`session.rs` `session_terms`）。拆开后词库属于输入法用户，应由终端随 `vocabulary` 带过去。
- **远程会话没有输出优化、去句末标点、繁简参数**。拆开后这些都要能由终端传参。

## 2. 拆完的样子

```
┌──────────── 飞音输入法（Windows / macOS，独立安装）──────────────┐
│ 热键 · 录音采集 · 浮层预览 / 编辑 · 上屏 · 托盘                  │
│ 场景感知（读前台窗口，结果随请求带给服务）                        │
│ 词库 · 使用统计（我的）· 处理环节开关（本机保存，每次随请求带上）  │
│ 首次使用连接向导：本机 flashasr / 连接码                          │
└───────┬──────────────────────────────────────────────────────────┘
        │ wss + 证书指纹钉扎（本机走 127.0.0.1，同一套代码）
        │ run-task（百炼同格式）+ PCM 16k
┌───────▼─────────────────────────── flashasr（识别服务）────────────┐
│ flashasr 前台进程（常驻、轻量）：                                 │
│   网关（TLS / 鉴权 / 协议）· 配对与终端管理 · 托盘 + 管理界面       │
│   终端档案（每终端：声纹；近场标定待远程实测后加）                 │
│   大模型统一配置（机主配一份，所有终端共用）                       │
│   文字处理：同音 · 去口水 · 数字规整 · 输出优化 · 单位补丁 · 繁简 · │
│     去句末标点 · 大模型翻译 —— 每个环节按本次请求的参数开关          │
│        │ 本机 IPC（沿用一期 transport / frame）                     │
│ flashasr-engine 引擎进程（重，按需拉起，崩了自动重拉）：            │
│   本地实时：VAD · SenseVoice 预览 · 1.7B 精解 · 强制对齐 · 接缝拼接  │
│   声纹剔除（用该终端档案里的声纹）                                   │
│   标点模型 · 离线翻译（要模型的文字环节）                           │
└──────────────────────────────────────────────────────────────────┘
```

**为什么把一期的「内核 + 网关」反过来：**

- 一期的内核是输入法本体，网关是可以崩的小弟。拆开后没有「本机输入」需要保护，最该常驻的是**网关 + 配对 + 界面**。
- 最容易崩、最吃内存的是**模型**，所以模型单独成进程，崩了由前台重拉，终端只看到一次 `task-failed`。
- IPC 帧格式（`asr_service/frame.rs`、`transport.rs`）一行不用重写，只是两端换了宿主。

## 4. 终端档案

**只存服务端才有、终端给不了的东西。** 处理环节开关不在这里（由前端每次传参，§5）。

| 项 | 内容 | 谁能改 |
| --- | --- | --- |
| 身份 | `device_id`、终端名、配对 key（一期已有） | 管理界面 |
| 声纹 | 该终端使用人的声纹（campplus 向量，几 KB），按使用自动累积；攒够之前不剔除，与今天本机做法一样 | 自动；终端设置页 / 管理界面可「重置声纹」 |
| 近场标定 | （以后）该终端麦克风的音量基线、音量沿用 —— 远程近场门开启时再加 | 自动 |

- 存在 flashasr 本机（同一个 SQLite 里每终端一行），以 `device_id` 为键。
- 会话按连接的 `device_id` 自动套用该终端档案。
- 终端只能操作**自己的**档案：网关加 `POST /v1/profile/voiceprint/reset`。
- **吊销终端 = 连档案一起删**，包括声纹。声纹属于生物特征数据，只存服务端本机、不外发，管理界面写明存了什么。
- 一个终端 = 一个人（Gavin 10-29），不分使用人。

仍是 `docs/ASR-PROTOCOL.md` v1（搬到本仓库 `docs/`），老终端（Python 参考客户端、手机端）不改也能用。

### 5.1 `run-task` 参数（处理环节开关全在这里）

| 参数 | 缺省 | 说明 | 状态 |
| --- | --- | --- | --- |
| `model` | — | 服务端忽略（只有本地实时一个引擎；照百炼写即可） | 一期已有 |
| `inverse_text_normalization_enabled` | `true` | 数字规整 | 一期已有 |
| `punctuation_prediction_enabled` | `true` | 补标点；`false` ⇒ 全部去标点 | 一期已有 |

| `feiyin.output_optimization_enabled` | `false` | 输出优化（大模型），用服务端统一配置 | **新增** |
| `feiyin.strip_trailing_punct` | `false` | 去句末标点（今天的快捷方式开关） | **新增** |
| `feiyin.chinese_script` | 服务端设置 | `simplified` / `traditional` | **新增** |
| `feiyin.scene` | 无 | 场景分类和风格提示，供输出优化用 | **新增** |

### 5.2 其它扩展

| 扩展 | 内容 | 老终端 |
| --- | --- | --- |
| 服务状态 | 网关加 `GET /v1/status`：协议版本、已开引擎、本地实时是否加载完、剩余路数、是否配了大模型 | 不调就不影响 |

## 6. 连接：首次使用向导

输入法第一次启动（或还没配好连接时）弹向导，二选一：

1. **本机的 flashasr**：flashasr 安装后在用户目录写一份本机配对文件（端口、本机 key、证书指纹，只有当前用户可读：Windows ACL / macOS 0600）。向导读到它就显示「检测到本机识别服务」，一键连上，不用输连接码。本机也走 wss + 指纹钉扎，和连远程同一套代码。
2. **另一台电脑的 flashasr**：扫码或粘贴连接码（一期已有的配对流程）。
两种都连不上 ⇒ 向导给出 flashasr 的下载说明，输入法在连上之前不能识别。

向导之后，设置页可以随时改连接方式。flashasr 还在加载模型时 ⇒ `/v1/status` 报「加载中」，输入法显示「识别服务启动中」，**不弹录音窗**（沿用「加载中不弹录音窗」）。

**本机两件套会不会变慢：** 一期远程会话的预览和终稿与本机共用同一套函数，差别只在多了一次本机回环收发。验收时用回放语料实测「松手到上屏」，增加不超过 20ms 才算合格。

**输入法怎么用这些代码：** 输入法只通过 Cargo 依赖引用 `flash-proto` 一个 crate（协议、客户端、配对）：开发期用本地路径，发版用 git tag 固定版本。文字处理整条在服务端，输入法不再带 ITN / 标点 / 大模型代码。场景感知（`src/scene/`）留在输入法。

**搬家方式：** 按上表复制文件，首个提交写明来源（voice-ime `db88090`），voice-ime 的历史留在原仓库。搬完的 crate 先原样编过、原测试全过，再动任何逻辑。

**flashasr 里删掉的：** `AsrModel::Performance` / `Accuracy` / `QwenAudioOnline` 及其加载、迁移、测试代码；179MB CTC 模型、972MB native 模型的加载路径。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 本机两件套比现在慢 | P3 验收硬指标：回放语料逐段比「松手到上屏」，增加 ≤ 20ms；回环 wss 不行就退到本机命名管道，协议帧不变 |
| Gavin 本机已积累的声纹丢失 | P0 把声纹改成按终端存取时，本机现有数据原地变成本机终端的档案；P3 切换只换宿主不换数据，不用重录 |
| 声纹是生物特征数据 | 只存服务端本机、不外发；终端能自己重置；吊销终端即删档案 |
| 服务端大模型费用集中在机主一人 | 管理界面按终端显示大模型调用次数，机主能看出谁用得多；终端不传输出优化参数就不产生费用 |
| 开输出优化后变慢 | 大模型调用耗时与今天在输入法里调一样；验收单列开 / 关两组耗时 |
| 文字处理分叉 | 规则只在 `flash-text` 一份；保留「包装层输出 == 直接调用」逐位护栏测试 |
| 版本错配（新输入法连旧服务） | `/v1/status` 报协议版本；输入法发现服务端不支持某参数就提示升级 flashasr |
| flashasr 未启动 / 崩溃 | 输入法托盘显示「识别服务未连接」并给出重连按钮；不静默失败 |
| 本机配对文件被别的程序读 | 只当前用户可读；本机 key 只对 127.0.0.1 来源生效，泄露也不能从外网用 |
| 外网暴露面 | 沿用一期：默认只放行专用网络、每终端一把 key、可吊销、强制指纹钉扎 |
