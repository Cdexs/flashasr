# 2026-11-12

## STOP-RESTART-FIX · 管理界面停止服务后再点启动无法启动且引擎无法加载修复（方案A）

- **问题现象**：在 `flashasr-ui` 管理界面点击「停止」按钮后，服务一旦停止再点击「启动」，服务卡在正在启动且无法正常启动，后台引擎 `flashasr-engine` 也无法正常加载。
- **根因排查**：
  1. **Windows 子进程句柄继承导致端口与锁文件泄漏**：`tray::open_ui` 拉起 `flashasr-ui.exe`、以及 `watch_settings` 自重启拉起新 `flashasr.exe` 时使用 `std::process::Command::spawn()`，Windows 下默认 `bInheritHandles = TRUE`。导致 `flashasr-ui.exe`（及其 WebView2 子进程）和 `flashasr-engine.exe` 继承了父进程 `flashasr.exe` 的 `7860` 端口监听 socket 句柄与 `flashasr.lock` 文件句柄。当停止服务退出旧 `flashasr.exe` 时，只要 `flashasr-ui.exe` 仍开着，端口 `7860` 依然被 `flashasr-ui.exe` 占用在 `LISTENING` 状态；再点启动时新 `flashasr.exe` 绑定 `7860` 报错 `os error 10048 (WSAEADDRINUSE): port 7860 unavailable`。
  2. **先拉引擎后绑端口 + 绑端口失败直接 `exit(2)` 自杀**：`run()` 原先先执行 `CoreLink::start()` 拉起 `flashasr-engine` 再调用 `serve()` 绑定端口；当端口绑定失败返回 `Err` 时，`main()` 直接调用 `std::process::exit(2)` 退出前台进程，导致托盘与 `watch_settings` 监控线程彻底死亡，同时 `flashasr-engine` 因 `stdin` EOF 立即跟着退出，表现为引擎也无法加载。
  3. **停止/退出未清理 `asr-gateway.json` 且 UI 缺少前台进程拉起兜底**：旧前台退出后残留过期的 `asr-gateway.json`，且 `flashasr-ui` 的 `server_set_enabled(true)` 只改写 `asr-service.json` 的 `enabled: true`，当前台进程已不存在时没有任何进程监听该配置变化并拉起服务。
- **修复方案（方案A，根治）**：
  1. **彻底阻断 Windows 句柄继承**：
     - `src/front/main.rs`：新增 `mark_non_inheritable_file` 与 `mark_non_inheritable_listener`（Windows 下调用 `SetHandleInformation(..., HANDLE_FLAG_INHERIT, 0)`），对日志文件 `flashasr.log`、单实例锁 `flashasr.lock` 以及 `7860` TCP 监听 socket 显式清除可继承标志；`watch_settings` 自重启改为 `spawn_relaunch`（Windows 下使用 `CreateProcessW` 并传 `bInheritHandles = false`）。
     - `src/front/tray.rs`：`open_ui` 改为 `spawn_detached_ui`（Windows 下使用 `CreateProcessW`、`bInheritHandles = false`、`DETACHED_PROCESS`），确保管理界面进程绝不继承前台任何 socket 或锁句柄。
  2. **调整启动顺序 + 端口重试 + 严禁因绑端口失败杀死常驻前台**：
     - `src/front/main.rs`：`run()` 改为**先调 `bind_listeners(settings.port, retry_bind)` 成功绑定端口，再调用 `CoreLink::start()` 拉起 `flashasr-engine` 并写出 `asr-gateway.json`**；对自重启或恢复场景支持最多 25 次 × 200ms（5s）的 `AddrInUse` 端口绑定重试；若最终仍失败，只清理 `GatewayInfo` 并记录日志，前台保持常驻等待配置变更，不再调用 `std::process::exit(2)`。
  3. **停止/退出清理 `asr-gateway.json` + 管理界面兜底拉起前台**：
     - `src/asr_shared/control.rs`：新增 `GatewayInfo::remove()`，在服务关闭、托盘退出、自重启前主动删除 `asr-gateway.json`。
     - `src-tauri/src/server.rs`：`server_set_enabled(true)` 写入配置后调用 `ensure_front_running()`，通过探测 `<data_dir>/flashasr.lock` 判断前台 `flashasr` 是否存活；若未运行则以无句柄继承方式自动拉起同目录下的 `flashasr`。
- **跨平台结论**：
  - **Windows**：通过 `SetHandleInformation` + `CreateProcessW(bInheritHandles = FALSE)` 彻底根除句柄继承引发的端口/文件锁泄漏。
  - **macOS / Unix**：Rust 标准库在 Unix 下创建文件与 socket 默认带 `FD_CLOEXEC`，`spawn_relaunch` / `spawn_detached_ui` / `spawn_detached_front` 在非 Windows 下使用 `Stdio::null()` 保持一致行为，无跨平台回退风险。
